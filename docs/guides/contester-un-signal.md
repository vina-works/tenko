# Contester un signal

Un signal est un constat isolé relevé par Tenko dans ton code : un mot de passe repéré à tel
endroit, une brique logicielle jugée trop ancienne, un fichier jugé trop gros. Les causes
affichées sous ta note regroupent ces signaux par nature.

Il arrive qu'un signal soit faux. Exemple courant : une chaîne de caractères qui ressemble
à une clé d'accès mais qui n'en est pas une, dans un fichier d'exemple.

## Comment contester

Sous la cause concernée, choisis « Contester ». Tu écris en une ou deux phrases pourquoi le
constat te paraît faux. Rien d'autre ne t'est demandé.

## Ce qui se passe ensuite

- Le signal cesse immédiatement de peser sur ta note : elle est recalculée sans lui.
- Il reste écarté aux analyses suivantes tant que la contestation n'est pas tranchée : tu
  ne le vois pas réapparaître à chaque nouvelle version de ton code.
- Une personne de l'équipe Tenko relit ton motif et tranche. Tu vois la décision.

Contestation retenue : le signal disparaît définitivement pour ton projet. Contestation
rejetée : il réapparaît avec la raison du refus, et tu peux le corriger comme les autres.

## Ce que contester n'est pas

Contester n'est pas masquer un problème gênant. Un signal écarté à tort est un risque que
tu gardes, sans plus le voir. Si tu hésites, lis d'abord ce que dit
[Les cinq axes](les-cinq-axes.md) sur la famille concernée, ou demande la correction et
juge sur le résultat : voir [Ce qu'est une preuve](ce-qu-est-une-preuve.md).

## Si tu contestes beaucoup

C'est un signal pour nous, pas pour toi. Tenko mesure la part de constats contestés par
projet ; au-delà de quelques pour cent, ce sont nos règles qui sont à revoir, et elles le
sont. Voir [Lire ta note](lire-ta-note.md) pour comprendre l'effet d'un changement de
version de règles.
